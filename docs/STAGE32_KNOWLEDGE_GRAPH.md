# Stage32：知识图谱最小读模型

## 目标

参考项目的图谱页会把一个训练主题中的评分问题、相似问题、低分点和最近复习信息组织起来，用于理解学习状态和辅助训练决策。本阶段先在 QTrace 中实现一个能运行、能解释、能从已有数据重建的最小版本：

```text
主题知识库 / 高频题库
        + 画像薄弱点 / SM-2 到期队列
        ↓
build_topic_graph(user_id, topic)
        ↓
GET /api/graph/{topic}
        ↓
前端 SVG 图谱 + 关系明细 + 专项训练入口
```

本阶段没有引入 Neo4j，也没有把关系边复制进数据库。图谱是 read model，打开页面时从已有事实源重新计算。

## 与参考项目的关系

参考项目的 `backend/graph.py` 会从用户的评分问题构建节点，并用向量表示与余弦相似度生成问题之间的边。QTrace 当前的高频题库、画像和复习队列已经具备形成学习关系图所需的业务数据，但还没有把 Embedding 作为图谱计算依赖。

因此当前实现是“行为方向一致的可解释替代”，不是对参考向量图算法的等价复制：

- 参考项目的相似关系偏语义相似；
- QTrace 用英文/数字 token 加中文二元字符片段计算确定性词法重叠；
- 参考项目从训练评分中构建问题状态；
- QTrace 直接读取已有 `topic_profiles` 与 `review_items`，并把 SM-2 到期点显式画成节点。

面试中应明确说明这个差异，不能把词法近似称为向量检索或语义图谱。

## 数据模型

### 节点

| 类型 | 来源 | 作用 |
| --- | --- | --- |
| `topic` | `topics.json` 与主题知识包 | 图谱根节点，表示当前训练领域 |
| `question` | 主题 `high_freq` 题库 | 表示可以进入专项训练的问题；状态为 `ready`、`weak` 或 `due` |
| `review` | SQLite `review_items` 中今日到期的条目 | 表示 SM-2 安排的待复习薄弱点 |

问题节点保留完整 `question`、`focus_area` 和主题 key，前端图上只截断显示标签；这样后续可以继续把某个节点交给训练入口，而不是只保留展示文案。

### 关系

| 关系 | 含义 |
| --- | --- |
| `contains` | 主题包含问题或待复习点 |
| `related` | 两个问题拥有足够的共同 token，适合放在同一小簇中理解 |
| `reviews` | 主题拥有一个今日待复习点 |
| `revisits` | 某个问题与一个待复习点存在词法关联，训练时可以回访该薄弱点 |

`weight` 是关系解释分数，不是模型置信度，也不会直接覆盖 SM-2 的 interval 或 ease factor。

## 关系算法

`backend/graph.py` 的计算过程是：

1. 按 `user_id` 和 `topic` 读取主题知识包、高频题库、主题画像和到期复习项；
2. 对高频题去重并最多取 24 个，避免图页面被异常大的题库拖垮；
3. 英文、数字和技术标识按 token 保留；中文额外生成相邻二元片段，让“召回率”和“离线召回率”能够产生可解释重叠；
4. 两个问题至少共享两个 token 且相似度不低于 `0.12` 时创建 `related` 边；
5. 问题与待复习点相似度不低于 `0.12` 时创建 `revisits` 边；
6. 输出节点、边和汇总统计，不写回任何业务表。

相似度使用：

```text
共同 token 数 / 两侧 token 集合大小的较小值
```

这是为了让结果在没有外部模型、没有网络和没有 Embedding API 时仍然稳定。后续如果接入真正的 Embedding，可以替换关系计算函数，而不需要改变前端节点契约或题库事实源。

## 接口与前端

后端新增：

```text
GET /api/graph/{topic}
Authorization: Bearer <token>
```

响应包含 `topic_name`、`mode`、`nodes`、`links` 和 `summary`。未知主题返回 400，未登录仍由统一认证依赖返回 401。

前端新增 `/graph` 页面：

- 按主题切换图谱；
- 展示高频问题、今日待复习、薄弱关联和关系边数量；
- 用 SVG 绘制主题、问题和待复习节点；
- 在关系明细中显示来源、关系类型、目标和权重；
- 通过现有 `/topic-drill` 入口继续训练，通过 `/knowledge` 返回编辑题库。

前端不依赖第三方图可视化库。当前布局是确定性的环形问题节点加底部复习节点，先保证可读、可调试和可复现，再考虑拖拽、缩放或更复杂布局。

## 为什么不直接使用 Neo4j

当前图谱的关系可以从题库、画像和复习表即时重建，尚没有需要独立图数据库才能表达的多跳查询，也没有把图关系作为写入事实。引入 Neo4j 会增加部署、同步、事务边界和用户隔离成本，反而不利于学习项目逐步理解。

等到出现以下需求，再评估图数据库或专门图索引：

- 需要跨主题、跨时间的多跳关系查询；
- 关系本身需要被用户编辑并保留历史；
- 图结构的计算量超过可接受的即时读模型成本。

## 验证结果

Stage32 新增回归测试覆盖：

- 相近问题能够生成 `related` 边；
- SM-2 到期项能够生成 `review` 节点和 `revisits` 边；
- 问题状态能够反映到期复习；
- 第二个用户看不到第一个用户的自定义题库；
- 未知主题被拒绝。

暂存工程验证结果：后端 `47 passed`，Python `compileall`、前端 `npm run typecheck` 和 `npm run build` 均通过。

## 面试追问准备

### 为什么图谱不是第二份数据库？

因为题库、画像和复习队列才是业务事实。图谱只在读取时生成，避免用户修改题库后还要同步删除旧边，也避免图谱和 SM-2 的真实状态分叉。

### 中文为什么不能简单按空格切词？

中文问题通常没有空格。当前版本保留技术词 token，再对中文字符生成二元片段，让“召回率”“离线召回率”这类局部重叠可以产生关系；它仍然只是词法近似，不能替代中文分词或 Embedding。

### 图谱怎样影响个性化训练？

当前阶段先做可解释展示：图谱告诉用户哪些题目相近、哪个薄弱点今天到期，并提供进入专项训练的入口。真正改变训练顺序仍由出题器、画像和 SM-2 队列负责；下一阶段可以把图上的高关联待复习点作为训练候选，但必须保留明确来源和测试。

### 为什么打开图谱不能直接更新复习状态？

查看不是学习行为。只有用户实际完成训练并产生复盘，系统才会更新画像和 SM-2；否则仅仅浏览页面就会污染长期画像。

## 当前限制与下一步

- 相似关系没有使用真实 Embedding，复杂同义表达可能无法连边；
- 当前只展示一个主题，尚未做跨主题知识关联；
- 图谱还没有直接驱动下一题选择，只提供解释和训练入口；
- 没有拖拽、缩放和大图布局优化。

下一步可以在不改变事实源的前提下，把“图谱上的待复习点 -> Agent 学习计划 -> 专项训练”串起来，再评估是否需要接入真实 Embedding 做语义关系。
