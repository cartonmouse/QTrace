# 阶段 63：端口校验先于合成数据创建

阶段 62 为端口冲突增加了可选的 `--backend-port`/`--frontend-port`。本阶段补上更细的安全边界：端口参数必须先通过 `1—65535` 校验，非法端口不能触发合成 SQLite 创建或后续 API 种子操作。

## 行为契约

```powershell
python scripts\seed_synthetic_browser_demo.py --backend-port 0
```

应直接输出失败状态并退出。校验发生在 `seed_browser_demo(...)` 之前，因此非法输入不会：

- 创建新的 SQLite 文件或 sidecar；
- 注册合成账号；
- 写入结构化简历、个人文档、知识库或图谱数据；
- 启动后端、前端或调用外部 API。

合法端口仍然可以通过：

```powershell
python scripts\seed_synthetic_browser_demo.py `
  --db data\qtrace-browser-demo-stage63.sqlite3 `
  --backend-port 8004 `
  --frontend-port 5177
```

输出的端点会反映选择的端口；端口是否被其他进程占用仍由运行态启动前的人工/本地检查负责，脚本不会自动停止未知进程。

## 回归与面试讲解卡

新增回归把 `seed_browser_demo` 替换为“不可被调用”的 fake，当端口为 `0` 时如果种子函数被调用，测试立即失败。这样验证的不只是“命令返回 1”，还验证了副作用顺序：先校验参数，再创建数据。

面试中可以这样解释：输入校验不仅要验证值域，还要放在有副作用的操作之前。即使本项目使用的是合成数据，也要避免错误命令产生无用数据库或半成品上下文；真实资料场景更不能依靠事后清理来兜底。

## 验证边界

- 本阶段没有读取真实数据库、简历、个人文档、浏览器存储或 API Key；
- 没有调用外部 API、部署、删除文件或执行 GitHub 提交推送；
- 回归使用 fake seed，不额外创建 SQLite；
- 浏览器人工彩排、正式全新目录复现、公开发布和 GitHub 提交推送仍未完成。

## 下一步

用户确认空闲端口和全新合成数据库后，按阶段 62/63 的命令启动隔离服务，再人工完成浏览器彩排；自动任务继续不接管现有浏览器或未知端口进程。
