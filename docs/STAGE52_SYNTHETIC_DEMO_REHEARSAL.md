# 阶段 52：合成数据本地彩排与讲解卡

## 目标

把阶段 51 的“应该如何演示”变成一条可以重复运行的后端合成链路，先验证项目主线的状态变化，再进行浏览器人工彩排。这样可以把“代码链路坏了”和“演示操作不熟”分开处理。

## 新增合成彩排

新增 `scripts/synthetic_demo_smoke.py`。它使用 FastAPI `TestClient`、临时合成 SQLite、随机合成账号和 StubProvider，依次验证：

1. 注册本地合成账号并启用离线 StubProvider；
2. 保存结构化简历和合成个人文档；
3. 生成五类项目追问卡；
4. 写入合成 RAG 高频题，更新一条合成薄弱点并读取知识图谱；
5. 让 Personal Agent 读取画像、到期复习和近期训练，创建 `draft` 学习计划；
6. 用户确认计划，再逐项完成，最终状态变为 `completed`。

脚本只输出步骤名称、状态和数量，不输出回答正文、数据库内容、API Key 或个人资料。默认数据库放到操作系统临时目录并使用唯一文件名；脚本不会删除生成的文件。如果传入 `--db`，也只能使用明确的合成数据库路径。

## 运行方式

在完整工程根目录运行：

```powershell
python scripts\synthetic_demo_smoke.py
```

预期看到八个 `PASS` 步骤和最后一个 `PASS synthetic demo rehearsal`。这是一条后端/API 彩排，不会自动打开浏览器，也不代表已经完成浏览器端到端测试。

## 浏览器人工彩排顺序

在前后端已启动、浏览器使用本地合成账号后，按下面顺序操作：

1. 打开“模型设置”，确认启用本地演示模型；
2. 在“简历编辑器”保存一个虚构的 AI Agent 项目，观察五类项目追问卡；
3. 进入“知识库”与“知识图谱”，选择 RAG 主题，观察问题节点、相近题和待复习节点；
4. 从追问卡或图谱问题进入“专项训练”，确认训练入口保留来源焦点；
5. 进入“个人 Agent”，请求“根据我的项目和近期复习安排一个训练计划”，展示工具 trace 和 `draft` 计划；
6. 点击确认，再从计划项进入训练或逐项完成，说明 Agent 不直接修改完成状态；
7. 使用阶段 49 的 fake provider 失败测试讲解错误区：输入恢复、用户主动重试、保留草稿按 `conversation_id` 精确加载。

人工彩排只使用虚构项目、虚构邮箱和 StubProvider。不要把真实简历、真实录音或真实 API Key 作为演示数据。

## 讲解卡：一条主线怎么讲

### 30 秒版本

“我把求职训练拆成三个层次：结构化简历提供个人事实，知识图谱和 SM-2 解释今天该练什么，Personal Agent 负责读取这些上下文并提出可确认的学习计划。模型只能提出工具调用，后端负责用户隔离、参数校验和 draft/confirm；训练和复盘再把结果写回画像与复习队列。”

### 90 秒版本

“用户先保存项目经历，系统确定性生成背景、职责、设计、验证和取舍五类追问卡。专项训练会合并用户焦点、领域题库、画像和 SM-2 到期项。图谱是从已有题库、画像和复习事实构造的只读视图，相近题只是候选入口。用户进入 Personal Agent 后，Agent 先规划工具调用，再读取简历、文档、画像、复习和近期训练上下文，最后生成回答；如果请求是生成计划，写工具只产生 draft，用户确认后才进入 active。模型或工具失败时，系统返回稳定错误状态，并尽量保留可恢复的输入或草稿。”

## 讲解卡：证据和边界

| 面试官关心什么 | 可展示的证据 | 不应声称什么 |
| --- | --- | --- |
| 项目能否运行 | `72 passed`、前端 build、local runtime smoke | 不声称已完成全新目录复现 |
| Agent 是否真实存在 | `/api/agent/chat` 的工具 trace、draft/confirm 接口、前端计划卡 | 不声称模型可以直接执行任意写操作 |
| 是否个性化 | 结构化简历、画像、SM-2 到期项、训练 focus 的合并链路 | 不声称画像已经用复杂模型自动推断一切 |
| 是否使用 RAG | 文档分块、EmbeddingProvider、citation 和 Agent 只读检索工具 | 不把确定性图谱边说成向量语义相似度 |
| 稳定性如何保证 | 失败错误码、工具降级、草稿保留、显式重试测试 | 不声称外部 LLM 永远可用 |
| 当前不足 | 文本优先、StubProvider、未部署、未做浏览器自动化 | 不把未完成的音频/WebSocket/多 Agent 能力包装成完成 |
