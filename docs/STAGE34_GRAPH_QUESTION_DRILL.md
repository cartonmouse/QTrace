# Stage34：图谱问题到精确训练

## 目标

Stage33 已经可以从主题图谱进入 Agent，生成主题作用域的复习计划。本阶段继续把图谱中的具体问题节点接到专项训练：点击 `question:<n>` 后，系统按当前用户的当前主题题库重新解析问题，并把它作为本轮第一个技术追问。

```text
图谱问题节点 question:2
        ↓
/topic-drill?topic=rag&graph_question_id=question:2
        ↓
后端按用户 + 主题重新解析题库索引
        ↓
个性化出题器生成候选，指定问题排到首位
        ↓
InterviewEngine 首个技术追问
        ↓
session 保存 ID + 完整问题文本
```

目标不是做一条平行的“图谱面试状态机”，而是让图谱成为现有专项训练的一个可审计入口。

## 为什么传 ID 而不是传完整问题

浏览器可以被用户修改，不能把前端提交的完整问题当成可信事实。如果请求直接携带：

```json
{"question": "用户自己伪造的问题"}
```

后端无法确认它是否来自当前用户的题库，也无法解释它为什么属于当前主题。

因此前端只携带：

```json
{"topic": "rag", "graph_question_id": "question:2"}
```

后端使用当前用户当前主题的 `get_topic_bundle` 重新读取题库，去重后按图谱同样的索引规则解析 `question:2`。只有解析成功才继续创建训练；完整问题文本由后端事实源生成并保存。

## 后端实现

### 请求与持久化字段

`StartInterviewRequest` 新增可选 `graph_question_id`。`sessions` 表和 `SessionView` 新增：

| 字段 | 用途 |
| --- | --- |
| `graph_question_id` | 记录触发训练的图谱节点 ID |
| `graph_question` | 记录后端解析出的完整问题文本 |

旧数据库通过 `_migrate_sessions` 增量增加列，旧 session 读取时使用空值默认，不要求重建数据库。

### 题目选择顺序

专项训练仍然会先执行已有 `build_drill_question_generator`：

- 读取主题知识上下文；
- 读取主题画像和 SM-2 到期项；
- 读取近期训练；
- 在真实 LLM 模式下生成结构化候选，或在 Stub 模式下用确定性规则生成候选。

如果存在合法 `graph_question_id`，后端把解析出的指定问题放到候选题列表首位，再保留其余候选题。这样：

- StubProvider 在第一次进入技术阶段时一定问指定题；
- OpenAI-compatible Provider 会收到包含指定题的高频题参考上下文；
- 后续项目深挖、行为问题和反问仍然沿用原有状态机与候选列表，不会把整场训练锁死在同一题。

同时，指定问题会作为 `图谱指定问题：...` 加入 requested focus，帮助动态出题器理解用户为什么选择它。

## 前端入口

知识图谱页面支持两种入口：

- SVG 问题节点点击后进入精确训练；
- “按此题训练”列表按钮进入精确训练。

专项训练页面会：

- 读取图谱接口确认问题文本并展示来源提示；
- 允许用户切换主题，但只有仍停留在原主题时才发送 `graph_question_id`；
- 开始请求时只提交 ID，不提交完整问题；
- 面试页展示 `GRAPH QUESTION SOURCE`，说明本次训练的触发节点和完整问题。

如果用户手动切换到其他主题，界面不会把原主题的节点 ID 发送给新主题，后端也会再次拒绝不属于当前题库的问题。

## 与状态机的边界

`InterviewEngine` 不知道“图谱”是什么，它只接收路由组装后的 `question_bank`。这是有意的模块边界：

```text
图谱模块：解析节点和来源
路由：校验 ID、组装候选题和 session metadata
出题器：根据画像/SM-2/LLM 生成候选
InterviewEngine：推进阶段和消息状态
Store：保存来源和训练结果
```

这样新增图谱入口不会把业务判断塞进状态机，也不会让状态机依赖知识图谱文件结构。

## 安全与兼容

- `graph_question_id` 只有专项训练模式允许使用；简历面试、JD 面试和录音复盘不能伪装成图谱问题训练；
- 主题和问题 ID 都在后端重新校验；
- 题库发生修改后，旧的 `question:<n>` 可能指向新的索引，因此训练 session 同时保存完整问题文本，保证历史记录仍然可读；
- 旧 session 的新增字段为空，不影响已有复盘和历史页面；
- 训练结束才会触发画像和 SM-2 写回，点击图谱节点或打开专项训练页面不会修改长期状态。

## 面试追问准备

### 为什么保存完整问题文本？

因为题库可能被用户编辑，未来同一个 `question:2` 可能指向不同文本。保存文本可以保留这次训练的历史事实，ID 则保留它当时的结构化来源。

### 为什么不直接把 `question_bank` 改成只有这一题？

那会让后续所有阶段重复同一个问题，也会绕过个性化出题器。当前做法是把指定问题放首位，其他候选保留给后续追问。

### 为什么状态机不直接读取图谱？

状态机只负责阶段和消息推进；图谱属于入口和上下文编排。分开后可以测试图谱解析、出题器和状态机各自的契约，降低耦合。

## 当前限制与下一步

当前 `graph_question_id` 只记录在训练 session，还没有进入 Agent 计划项。如果用户先从图谱进入 Agent，再从计划进入训练，计划目前只携带主题和复习点文本。下一步可以增加可选的问题节点来源元数据，让“图谱问题 -> Agent 计划 -> 训练 session”整条链路都能追溯到同一个节点。
