# 阶段 53：浏览器彩排前置检查与操作卡

## 阶段边界

本阶段原计划在本地浏览器中使用合成账号完成一轮人工彩排。但自动任务当前不能安全假设浏览器中的登录态：现有页面可能属于用户的本地账号，自动创建或登录新账号也会改变浏览器和本地应用状态。因此本阶段不读取浏览器存储、不读取页面中的个人资料、不自动创建账号，也不把浏览器人工彩排误报为完成。

为了继续推进独立工作，新增 `scripts/frontend_route_preflight.py`，在不打开浏览器的情况下检查前端源码中关键路由、Agent 恢复操作和样式标记是否存在。它是人工彩排前的结构门禁，不替代真实点击。

## 运行方式

在完整工程根目录运行：

```powershell
python scripts\frontend_route_preflight.py
```

脚本只读取 `frontend/src/App.tsx` 和 `frontend/src/styles.css`，检查：

- 简历编辑器、专项训练、JD 定向、Copilot、Agent、知识库、图谱、历史和画像等入口路由；
- “重新发送”“加载保留草稿”和 `role="alert"` 等可恢复交互标记；
- Agent 错误操作区和工具 trace 的样式标记。

它不访问 HTTP，不读取 localStorage/cookie，不启动前端，不读取数据库或个人文档。

## 待用户执行的人工彩排

用户在本地确认使用合成账号后，可以按以下顺序操作：

1. 启动后端和前端，打开本地页面；
2. 使用虚构邮箱注册账号，模型设置选择 StubProvider；
3. 保存一个虚构的 AI Agent 项目，检查五类项目追问卡；
4. 进入知识库和图谱，检查问题节点、相近题和待复习节点；
5. 从追问卡或图谱问题进入专项训练，确认来源焦点存在；
6. 进入 Personal Agent，生成学习计划 draft，确认计划，再完成一个计划项；
7. 用 fake provider 失败用例检查输入恢复、显式重试和保留草稿提示；
8. 记录页面截图位置、最容易卡住的操作和面试口述中的薄弱点。

这部分需要真实用户在本地浏览器中确认账号状态后执行，本阶段不把它作为自动化完成项。

## 面试讲解卡

### 页面操作和后端状态如何对应？

简历编辑器保存的是当前用户的结构化简历版本；追问卡是确定性读模型。Agent 的消息请求会先创建或恢复对话，再执行白名单工具；学习计划写工具只产生 `draft`，用户确认后才是 `active`。专项训练从计划项进入时保存来源关系，复盘和完成动作再更新训练事实。

### 为什么静态路由检查不能代替浏览器测试？

源码中存在路由只能证明页面入口和关键标记没有被意外删除，不能证明登录态、请求返回、页面状态更新和视觉布局正确。因此它只能减少人工彩排前的结构性错误，不能代替真实点击和浏览器端到端测试。

### 当前阶段为什么没有自动注册一个演示账号？

自动任务不应猜测或接管现有浏览器账号，也不应在未明确确认的情况下创建新的浏览器账户状态。后端合成彩排已经覆盖同一条业务主链；浏览器侧留给用户在明确的合成数据边界下执行，结果更容易解释和复现。

## 验证结果

- 新增前端路由/恢复 UI 静态契约测试；
- 后端合成彩排、后端全量回归、前端构建和运行态检查继续作为独立证据；
- 本阶段没有读取浏览器存储、真实简历、个人文档或 API Key，没有创建浏览器账号，没有部署、删除文件或提交推送 GitHub。
