# Stage27：项目追问卡与个人证据映射

## 目标

结构化简历解决了“项目事实如何保存”，但面试准备还缺少“面试官会怎么追问”。本阶段根据项目字段确定性生成一组可解释的追问卡，并用项目名称检索个人文档库中的详细证据。

每个项目默认生成五类问题：

1. 背景与目标：项目解决什么问题，用户为什么需要它；
2. 个人职责：候选人具体负责哪些模块和工作；
3. 关键设计：为什么选择技术和架构，替代方案代价是什么；
4. 效果验证：如何证明方案有效，指标、基线和故障验证是什么；
5. 复盘取舍：最难的工程取舍是什么，如果重做会怎样改进。

## 为什么先用确定性模板

面试追问卡是训练入口和用户可见的准备清单，不能每次刷新都随机变化。模板有三个优点：

- 输入字段和输出问题有明确映射，面试时能解释“这道题为什么出现”；
- 不依赖真实 LLM，测试和本地演示稳定；
- 以后可以让 LLM 在这组固定主题下润色具体措辞，但不会改变问题覆盖范围。

当前每张卡都记录 `field_refs`，例如：

```json
{
  "category": "关键设计",
  "field_refs": ["technologies", "highlights"],
  "document_query": "问迹 QTrace 关键设计",
  "evidence": []
}
```

这让候选人知道应该从哪几个简历字段准备答案，也让后端知道应该用什么查询去找项目文档。

## 证据映射

追问卡生成后，后端把“项目名称 + 问题类别”作为本地检索查询：

```text
结构化简历项目
  -> 生成追问卡和 document_query
  -> PersonalDocumentService 本地检索
  -> 返回最多 3 个个人文档片段
  -> 保留 citation、版本和文档块序号
```

如果个人文档库中没有匹配资料，卡片仍然会显示问题，只是不显示证据引用。这是有意的：缺少资料应该成为准备提醒，而不是让系统编造一段项目事实。

查询仍然显式带 `user_id`，并且使用 Stage25 的当前文档版本检索和 Stage24 的 citation。文档证据是辅助材料，不会自动写入结构化简历，也不会自动修改画像或学习计划。

## 接口

```text
GET /api/resume/editor/question-cards
```

响应包含：

- `resume_version`：生成这组卡片时使用的结构化简历版本；
- `project_name`、`category`、`question`、`purpose`；
- `field_refs`：建议准备的结构化字段；
- `document_query`：用于个人文档检索的可解释查询；
- `evidence`：最多 3 个带 citation 的个人文档检索结果。

接口是只读的；没有项目时返回空数组，不会创建任何持久化记录。

## 前端行为

结构化简历页面增加“项目追问卡”区：

- 显示当前简历版本和卡片数量；
- 展示问题、出题目的和字段证据；
- 有匹配个人文档时显示 citation 标签；
- 没有匹配资料时只显示问题，提醒用户补充项目文档。

这组卡片首先是面试准备清单，不会替代 InterviewEngine 的状态机。Stage28 已在卡片上增加“进入专项训练”按钮，把卡片问题作为可追踪的训练 focus，并保留卡片来源。

## 面试追问卡

### 为什么不是让 LLM 直接生成所有追问？

追问卡需要稳定覆盖背景、职责、设计、验证和取舍五类能力。先用确定性模板保证覆盖和可测试性，再让 LLM 负责针对岗位或用户画像润色问题，职责更清晰，也容易处理模型失败。

### 为什么证据检索只用项目名和类别？

这是一个最小、可解释的 seam。项目名称把简历字段和个人文档连接起来，问题类别进一步限定“背景/设计/验证”等语境；未来可以加入技能词、JD focus 和用户画像，但不会改变工具的只读边界。

### 没有个人文档证据时为什么不报错？

追问卡本身仍然有价值，它能暴露“简历上写了项目，但没有可引用细节”的准备缺口。空证据是可观察状态，应该提示用户补充材料，而不是阻断整个编辑器或伪造回答。

### 追问卡会修改简历或画像吗？

不会。接口只读取当前结构化简历和个人文档，返回问题与证据；它不写入简历版本、不改变 SM-2、不创建学习计划。用户明确点击后，未来才可以进入专项训练或生成计划。

## 验证结果

- 一个项目生成五类追问卡；
- 每张卡含对应的 `field_refs` 和解释性 `document_query`；
- 个人文档存在匹配内容时返回带版本化 citation 的证据；
- 没有项目时返回空数组；
- 结构化简历更新后卡片的 `resume_version` 同步到最新版本；
- 暂存工程完整后端测试 `43 passed`；Python compileall、前端 typecheck 和生产构建通过。

## 当前限制

- 当前问题模板不感知具体岗位 JD，也没有根据画像动态调整难度；
- 证据映射使用项目名和类别的本地检索，没有 reranker 或 LLM query rewrite；
- 当前问题模板仍不感知具体岗位 JD，也没有让 Agent 自动从卡片生成学习计划；
- 训练入口虽然会合并 JD 学习计划焦点、画像和 SM-2 队列，但卡片本身仍然是只读来源，不会自动改变计划状态或复习间隔；
- 真实资料联调和外部部署仍需单独确认。
