# Stage36：图谱相近问题候选

## 目标

知识图谱的 `related` 边已经能够说明两个问题在当前确定性规则下相近。本阶段把这层关系转化为可选的后续练习候选：用户点击一个问题节点时，可以查看相近问题；Agent 读取指定问题时，也会把最多三个相近问题作为计划元数据返回。

```text
question:1 --related--> question:2
       ↓
图谱节点 related_question_ids
       ↓
前端相近问题候选 / Agent related_questions
       ↓ 用户明确点击
专项训练或新的 Agent 计划入口
```

候选不会自动追加到学习计划，防止相似度误差和图谱规模把用户的训练任务无限放大。

## 为什么从已有边派生

如果前端、Agent 和图谱后端分别再实现一次相似度计算，会出现：

- 同一个问题在不同页面得到不同邻居；
- 规则阈值分散，修改时难以回归；
- Agent 的建议无法解释“这道题为什么被推荐”；
- 图谱 `link_count` 与候选列表不一致。

因此 `build_topic_graph` 先构建唯一的 `related` 边，再为每个问题节点派生 `related_question_ids`。Agent 和前端都消费同一份关系结果。

## 响应模型

问题节点新增：

```json
{
  "id": "question:1",
  "type": "question",
  "question": "如何评估 RAG 的召回率和准确率？",
  "related_question_ids": ["question:2"]
}
```

ID 列表是当前图谱中的邻居索引，不是新的事实表。完整问题文本仍然从节点本身读取；关系强度仍然由对应 `related` link 的 `weight` 表示。

## Agent 返回

Stage35 的 `read_graph_question` 工具现在返回：

```json
{
  "id": "question:1",
  "topic": "rag",
  "question": "如何评估 RAG 的召回率和准确率？",
  "related_questions": [
    {
      "id": "question:2",
      "topic": "rag",
      "question": "RAG 召回率和准确率如何通过离线评测验证？",
      "focus_area": "综合能力",
      "weight": 0.42
    }
  ]
}
```

Agent 生成的 `graph_question` 计划项和计划 source 会保存最多三个候选，但只作为元数据：

- 计划仍然只有一个明确的图谱问题任务；
- 候选不会自动生成新的 `learning_plan_item`；
- 用户可以在图谱页或计划回答中选择后续练习；
- 选择后再次走主题和问题 ID 的后端校验。

这样计划的核心目标仍然清楚，同时保留探索相近知识的空间。

## 前端交互

知识图谱页现在支持：

1. 点击 SVG 问题节点，高亮当前节点；
2. 展示它的相近问题数量和候选列表；
3. 从候选列表直接进入精确专项训练；
4. 把候选问题单独交给 Agent 制定计划；
5. 在所有入口上保持 `topic + graph_question_id` 结构化传递。

“按此题训练”按钮仍然直接进入 Stage34；“让 Agent 制定计划”仍然进入 Stage35。相近问题只是新增的候选层，不改变原有入口语义。

## 为什么不自动扩展计划

`related` 只说明词法重叠达到阈值，不说明用户一定需要再练这道题。自动扩展会产生三个风险：

- 同义或同上下文问题被重复安排；
- 计划长度和用户时间预算失控；
- 用户无法区分 SM-2 到期任务和图谱探索任务。

因此当前原则是：

```text
图谱可以主动解释，计划扩展必须用户确认。
```

未来即使要提供“加入计划”按钮，也应该由用户逐项选择，并把来源类型区分为 `graph_neighbor`，不要把它伪装成 SM-2 到期任务。

## 安全与数据边界

- 邻居只来自当前用户当前主题的题库图；
- Agent 工具调用时重新构建图谱，不信任前端提交的邻居文本；
- 候选不会写入画像、复习队列或学习计划状态；
- 用户点击候选后，专项训练入口再次验证问题 ID；
- 边权是关系解释分数，不是掌握度、录用概率或 LLM 置信度。

## 验证结果

新增断言覆盖：

- 两道相近 RAG 题互相包含对方的 `related_question_ids`；
- Agent 计划 source 和计划项保留相近题候选；
- 原有 Agent 图谱问题校验、精确训练、SM-2 过滤和用户隔离测试保持通过。

暂存工程验证结果：后端 `50 passed`，Python `compileall`、前端 `npm run typecheck` 和 `npm run build` 均通过。

## 面试追问准备

### 为什么不直接让 Agent 自己生成相似题？

因为相似题是知识关系，应该有稳定来源。当前 Agent 只读取图谱已有边，避免模型凭空扩展题目或把不存在的问题写进计划。

### 为什么候选不自动加入计划？

关系边不是用户意图，也不是 SM-2 到期信号。自动写入会产生副作用和任务膨胀，所以先展示候选，用户点击后才进入下一步。

### related 边权能否用来表示掌握度？

不能。边权只表示两个问题在当前词法规则下的关系强度；掌握度来自训练评分和 topic profile，复习优先级来自 SM-2，三个概念必须分开。

## 当前限制与下一步

当前候选仍来自确定性 token/中文二元片段，复杂同义表达可能漏连或误连；候选排序也没有利用用户实际训练结果。下一步可以记录用户对候选的选择和训练结果，用于评估关系是否真的提高了学习效率，再谨慎考虑真实 Embedding。
