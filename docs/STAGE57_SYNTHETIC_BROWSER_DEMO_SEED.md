# 阶段 57：合成浏览器演示账号种子

阶段 52 已经用 TestClient 验证了后端主链，阶段 53 则把浏览器人工彩排留给用户。本阶段补上两者之间的操作缝隙：提供一个只创建全新 SQLite 文件的合成账号种子脚本，让用户可以在不触碰现有数据库和真实资料的前提下启动一套可登录的浏览器演示环境。

## 脚本做什么

`python scripts\seed_synthetic_browser_demo.py` 会在新的 SQLite 路径中创建：

- 一个 `example.test` 合成邮箱和固定合成密码；
- StubProvider 本地演示模型配置；
- 一份结构化简历和五类项目追问卡；
- 一条合成个人文档；
- RAG 高频问题和知识图谱入口。

脚本只输出数据库路径、合成账号和准备步骤，不输出访问令牌、文档正文或任何真实资料。默认数据库写入操作系统临时目录；传入 `--db` 时，目标路径必须不存在。脚本会拒绝已有数据库及 SQLite sidecar，不覆盖、不删除任何文件。

## 为浏览器彩排准备独立数据库

在工程根目录执行：

```powershell
python scripts\seed_synthetic_browser_demo.py --db data\qtrace-browser-demo.sqlite3
$env:REBUILD_DB_PATH = (Resolve-Path 'data\qtrace-browser-demo.sqlite3').Path
$env:REBUILD_DATA_DIR = (Resolve-Path 'data').Path
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8002
```

脚本最后会打印本次生成的 `EMAIL` 和 `PASSWORD`，用户把它们输入本地登录页即可。另开一个终端启动前端：

```powershell
Set-Location frontend
npm run dev
```

浏览器打开 `http://127.0.0.1:5174`，然后按阶段 53 的操作卡检查简历编辑器、追问卡、图谱、专项训练和 Agent 的 draft/confirm。种子脚本不会自动打开浏览器、不会自动登录、不会创建真实账号，也不会自动生成学习计划；这些页面动作仍由用户人工完成。

## 为什么拒绝已有路径

本地 `data\rebuild.sqlite3` 可能包含用户已经使用过的账号。为了让演示命令不靠猜测判断数据库是否真实，脚本采用更保守的规则：目标文件、`-wal`、`-shm` 或 `-journal` 任意一个存在就直接失败。用户应换一个全新的文件名，或在确认不再需要该合成演示库后由人工处理；本项目不会自动删除旧文件。

## 面试讲解卡

### 为什么另做种子脚本，而不是自动操作浏览器？

种子脚本负责可重复地准备后端事实，浏览器仍由人操作。这样既能让登录、页面请求和状态变化真实发生，又不会让自动任务接管用户现有浏览器登录态。它证明“可以准备一套合成演示数据”，不证明浏览器 E2E 已经通过。

### 为什么不直接把合成账号写进正式数据库？

正式数据库的边界可能包含用户自己的训练历史。脚本默认使用临时路径，并且对传入路径做存在性门禁；用户需要显式选择一个新文件并通过 `REBUILD_DB_PATH` 启动后端。数据隔离由操作边界和应用的 `user_id` 查询共同保证。

### 这和真实 LLM 联调有什么关系？

没有直接关系。种子脚本固定使用 StubProvider，不联网、不读取 API Key。它只为前端和 Agent 状态机提供合成上下文；真实 LLM/Embedding 联调仍按阶段 44/45 的独立门禁执行。

## 验证结果

- 暂存与正式工程完整回归为 `83 passed`，Python compileall、前端 typecheck/build、合成主链和本地运行态检查继续作为独立证据；
- 本阶段没有读取真实数据库、简历、个人文档或浏览器存储，没有调用外部 API，没有部署、删除文件或提交推送 GitHub。
