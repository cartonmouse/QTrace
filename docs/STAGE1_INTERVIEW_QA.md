# Stage 1 面试追问卡

## Q1：为什么没有把模型调用直接写在 FastAPI 路由里？

因为路由应负责鉴权、输入校验和编排；模型供应商是可替换的基础设施，面试流程应依赖一个稳定的 provider 接口。这样可以用本地 stub 做测试，也能在以后接入真实 LLM 时不改状态机。

## Q2：状态机为什么要显式维护 phase 和 phase_question_count？

只把聊天消息交给模型会让流程边界不可控。显式状态可以决定什么时候继续追问、什么时候切换到项目深挖或行为问题，并且可以设置每阶段上限，防止模型输出异常导致会话无限循环。

## Q3：如何保证用户 A 不能读取用户 B 的会话？

每次读取会话都用 `WHERE id=? AND user_id=?`，而不是只按 session id 查询；token 的 subject 决定当前 user id。测试中用两个账户验证了跨用户读取返回 404。

## Q4：为什么登录后还需要 ProviderGate？

登录只证明身份，不证明当前用户有可用的模型能力。LLM 负责生成/评估，Embedding 负责知识与记忆检索，所以配置状态是独立的产品门禁。

## Q5：stub provider 有什么价值？

它不是为了冒充真实 AI，而是为了隔离网络和费用依赖，先验证路由、状态机、持久化和前端交互。真实 provider 只替换接口实现，系统结构保持不变。
