# 阶段 58：真实 Agent Smoke 输出脱敏

阶段 45 已经建立了真实 LLM/Agent 的合成上下文 smoke 边界，阶段 44 也已经为 Embedding smoke 增加了错误脱敏。本阶段补齐两者之间的一致性：即使未来供应商或 HTTP 客户端异常文本包含 API Base 或凭据片段，Agent smoke 也不会直接把它们打印出来。

## 变更内容

`scripts/agent_llm_smoke.py` 的真实联调路径仍保持原有门禁：

- 只读读取指定用户的聊天 Provider 配置；
- 只有 `openai`、Base、Model 和 Key 都存在时才构造模型并发起调用；
- 请求只使用固定合成消息、合成画像、合成到期复习项和空训练历史；
- 成功时只输出 host、model、工具名、耗时和回答长度，不输出 Key 或完整回答。

本阶段新增 `_redact` 边界：失败信息会替换 API Key 和完整 API Base，压缩换行并限制长度后再输出。正常 Provider 当前只返回稳定的通用错误，这一层是针对供应商异常格式变化的纵深防御。

## 回归测试

新增测试使用合成配置和 fake `build_agent_model`，人为构造同时包含合成 Key 与 endpoint 的异常，验证：

- smoke 返回失败状态；
- 输出不包含 Key；
- 输出不包含完整 endpoint；
- 输出仍保留 `<redacted>`，便于定位“发生了脱敏”而不是静默吞错。

测试不会发起网络请求，也不会读取真实数据库或个人文档。

## 面试讲解卡

### 为什么 Embedding smoke 已经脱敏，Agent smoke 还要再做一层？

两个 Provider 的异常来源和演进路径不同，不能假设其中一个模块的脱敏逻辑会自动覆盖另一个模块。smoke 脚本是面向运维和开发者的输出边界，因此每个脚本都要在自己的最后输出层做一次凭据清理。

### 为什么不直接打印供应商原始错误？

原始错误可能包含 endpoint、请求片段甚至鉴权信息；对定位问题来说，HTTP 状态、阶段和稳定摘要已经足够。真实业务 API 也沿用同一原则，不把供应商异常原文直接回传前端或交给 Agent。

## 验证结果

- 新增 Agent smoke 失败脱敏回归；暂存与正式工程完整回归实测为 `84 passed`；
- Python compileall、前端 typecheck/build、合成主链、本地运行态和交付前置检查继续通过；
- 本阶段没有发起真实 LLM/Embedding 网络请求，没有读取 API Key 内容、真实简历或个人文档，没有部署、删除文件或提交推送 GitHub。

## 下一步

用户仍需在合成数据库上完成一次浏览器人工彩排；若之后再次进行真实模型联调，应继续使用本脚本的合成上下文并只记录脱敏后的摘要。
