# 阶段 59：回归临时产物的公开仓库边界

阶段 58 之后，正式工程的交付检查提示了大量本地回归临时目录。它们是测试生成的 SQLite/缓存目录，不是业务代码，也不应进入 GitHub。本阶段补齐 `.gitignore` 与复现前置检查的契约，不删除已经存在的目录。

## 新增忽略规则

`.gitignore` 新增以下模式：

```text
qtrace_stage*_pytest_tmp/
qtrace_stage*_formal_pytest_tmp/
qtrace_stage*_target_tmp/
qtrace_stage*_tmp/
```

这些模式覆盖阶段回归使用的 `--basetemp`、定向测试和临时工作目录。数据库、日志、`data/`、前端依赖和构建产物仍由原有规则保护。

## 为什么不删除目录

当前任务明确禁止自动删除文件。忽略规则的作用是防止未来 `git add` 误把它们纳入提交，不是把现有工作区清理掉。`repository_preflight.py` 仍会报告本地产物，提醒发布前人工检查；报告本身不代表代码失败，也不会自动清理。

## 复现前置检查

`scripts/reproduction_preflight.py` 现在把两类主要回归临时目录作为必需忽略规则验证：

- 缺少规则时返回配置错误，阻止把复现准备误判为完整；
- 规则存在时继续只读检查核心文件、前端脚本和本地数据边界；
- 它不读取 SQLite 内容、不启动服务、不安装依赖、不调用外部 API。

## 面试讲解卡

### 为什么 `.gitignore` 和发布前扫描要同时存在？

`.gitignore` 是日常误提交的第一道防线，静态扫描是提交前的第二道提醒。前者减少风险，后者帮助发现已经存在或命名不符合预期的本地产物；二者都不能替代人工确认，也不应该通过自动删除来“修复”工作区。

### 忽略目录是不是意味着可以把真实资料放进去？

不是。忽略规则降低误提交概率，但不会加密文件、阻止本地读取或阻止上传。真实简历、个人文档和 API Key 仍不应进入项目数据目录；本项目的自动化演示继续使用合成数据。
