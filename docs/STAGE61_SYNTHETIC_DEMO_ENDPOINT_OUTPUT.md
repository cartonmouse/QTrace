# 阶段 61：合成浏览器演示端点输出

阶段 60 已经把隔离浏览器彩排约定为“新 SQLite + 后端 `8003` + 前端 `5175` + Vite `REBUILD_API_TARGET`”。本阶段让种子脚本直接打印这组无敏感信息的端点，减少人工彩排时复制端口和代理地址出错的机会。

## 脚本输出

运行：

```powershell
python scripts\seed_synthetic_browser_demo.py --db data\qtrace-browser-demo-stage61.sqlite3
```

如果推荐端口被占用，可以显式指定一组空闲端口，例如 `--backend-port 8004 --frontend-port 5177`；脚本会把自定义值写入后续端点输出。

脚本仍只接受不存在的新 SQLite 路径，成功后除了合成账号和数据库环境变量，还会输出：

```text
BACKEND_URL=http://127.0.0.1:8003
FRONTEND_URL=http://127.0.0.1:5175
REBUILD_API_TARGET=http://127.0.0.1:8003
```

这些是本地服务地址，不是外部 API 地址，也不包含 API Key。输出的 `REBUILD_API_TARGET` 应在前端终端中设置；`REBUILD_DB_PATH` 和 `REBUILD_DATA_DIR` 应在后端终端中设置。端点只是启动提示，不会自动启动服务、打开浏览器或登录账号。运行态检查和端口占用处理见 `docs/STAGE62_ISOLATED_RUNTIME_SMOKE.md`。

## 为什么让种子脚本打印端点

如果脚本只输出数据库路径和账号，用户仍需从另一份文档手工抄写后端/前端端口，容易出现“数据库是新的，但前端仍代理到旧后端”的配置错误。把端点作为脚本的确定性输出，可以让人工操作按同一份结果启动服务；真正的请求隔离仍由环境变量和不同端口共同保证。

## 面试讲解卡

### 这是不是把部署配置写死了？

不是。`8003` 和 `5175` 是本地合成彩排的推荐默认值，用来避开常规开发实例；Vite 仍支持通过启动参数改前端端口，后端也可以改端口。脚本输出的是默认操作卡，不是云端部署配置。

### 为什么输出账号密码可以接受？

脚本生成的是 `example.test` 合成账号和固定演示密码，数据库路径也要求全新文件。它不读取或打印真实账号、真实简历、个人文档或 API Key；公开仓库中不应保存运行输出。

### 端点输出能证明浏览器 E2E 吗？

不能。它只减少启动配置错误；登录、页面请求、图谱跳转、Agent draft/confirm 和视觉布局仍需在合成数据下人工验证。

## 验证结果

- 新增回归覆盖种子脚本打印 `8003`、`5175` 和 `REBUILD_API_TARGET`；
- 种子脚本仍拒绝已有数据库/sidecar，不删除文件、不联网、不启动服务；
- 本阶段未读取真实数据库、简历、个人文档、浏览器存储或 API Key，没有部署或执行 GitHub 提交推送；
- 浏览器人工彩排、正式全新目录复现、公开发布和 GitHub 提交推送仍未完成。

## 下一步

用户可以在确认全新合成数据库路径后，直接依据脚本输出启动隔离后端和前端，再人工完成浏览器彩排；自动任务继续不接管现有浏览器状态。
