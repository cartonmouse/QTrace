# 阶段 20：发布前行为收口

## 背景

Stage15–19 已经形成了 Personal Agent → 学习计划 → 专项训练 → 复盘的主链。本阶段不新增业务模块，而是针对代码审查发现的边界问题做发布前收口。

## 修复内容

### 1. Agent 写工具的意图边界

`_is_plan_request()` 增加否定表达判断。类似“暂时不要生成学习计划，只解释我的薄弱点”的请求不会触发 `create_learning_plan`。写工具仍必须经过：

```text
用户明确请求
  -> 规划结果归一化
  -> 读取画像 / 到期复习 / 近期训练
  -> create_learning_plan
```

### 2. 计划生成必须读取近期训练

无论真实 LLM 规划器返回哪些读取工具，计划请求都会补齐 `read_profile`、`read_due_reviews` 和 `read_recent_sessions`，再执行写工具。这样计划不会只根据静态画像和今日队列生成，能够使用近期分数、模式和复盘薄弱点。

### 3. 复盘页面失败可见

Review 页面加载会话失败时不再永久停留在 loading 状态，而是显示错误信息和返回历史记录入口。关联学习计划读取失败仍只影响计划卡，不会遮蔽已经成功读取的复盘结果。

### 4. 计划项完成动作的语义

复盘页只有在会话 `is_finished` 且存在 `review` 时才显示完成计划项动作。Agent 计划卡仍允许已完成计划项“再次训练”，与后端允许重复训练的行为保持一致；再次训练仍然记录原计划来源，但不会自动改变计划状态。

## 面试追问速答

### 为什么不能只用关键词判断 Agent 意图？

关键词只能作为正向候选，必须先排除否定表达，否则“不要生成计划”也可能包含“生成计划”关键词并触发写操作。当前实现采用保守策略：识别到否定计划表达时不写入，优先保护用户意图。

### 为什么 LLM 规划结果还要由后端补齐读取工具？

模型输出是建议，不是权限和业务契约。计划生成依赖近期训练信号，因此后端在归一化阶段补齐必需读取，保证不同模型的规划结果都遵守相同数据前置条件。

### 为什么已完成计划项还要允许再次训练？

完成计划项代表一次行动记录，不代表永久掌握。再次训练可以产生新的复盘证据；后端只保存来源关联，是否再次完成由计划状态和用户操作决定。
