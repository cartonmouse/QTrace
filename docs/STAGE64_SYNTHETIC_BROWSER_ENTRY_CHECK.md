# 阶段 64：合成浏览器认证入口检查

阶段 64 把一次真实的本地合成浏览器页面检查沉淀成可回归的前端入口契约。自动任务在隔离的 `8004/5177` 环境打开 QTrace，确认登录页和注册页的标题、表单和按钮可见；由于浏览器安全规则要求在页面中输入密码前临时确认，本阶段没有代填密码，也没有把登录或完整 E2E 说成已完成。

## 页面检查结果

合成浏览器页面已观察到：

- 登录入口和注册入口按钮；
- 邮箱、密码输入框；
- “进入学习工程”和“创建本地账户”操作按钮；
- “把一次面试，变成一条可追踪的成长链。”页面标题；
- 注册页的称呼、邮箱、密码字段。

浏览器只使用了新建的合成数据库和本地服务。检查结束后只停止本阶段启动的后端/前端进程；没有停止已有的 `5175/5176` node 进程，没有删除合成数据库，没有读取 cookie/localStorage 或真实资料。

## 新增前置契约

`scripts/frontend_route_preflight.py` 新增 `REQUIRED_AUTH_MARKERS`，检查 `App.tsx` 中的登录/注册提交入口：

```text
进入学习工程
创建本地账户
```

这项源码检查可以防止认证入口被意外删掉，但不能证明浏览器表单提交、密码验证、token 保存或后续页面请求成功。后者仍需要用户在合成账号下人工完成。

## 面试讲解卡

### 为什么只检查按钮文案？

按钮文案不是功能证明，而是最小的源码契约，能在构建前发现登录/注册入口被误删。真正的页面检查还要看 DOM 是否渲染；本阶段浏览器已验证渲染，但没有输入密码和提交登录，因此仍保留完整 E2E 边界。

### 为什么不自动输入合成密码？

即便密码是合成的，浏览器自动化策略仍把密码输入视为敏感操作，需要临时确认。本阶段不等待用户确认，所以停在登录页/注册页入口检查，不把未执行的登录写成已完成。
